## 1. Product identity

**Funny One** is the pass-and-play sibling of «Чепуха 37» under the umbrella brand «Семейная
Чепуха» (Funny Family): **one device, no network, ever.** 1–7 local players share a phone or
tablet, taking turns to answer; nothing leaves the device during play, and — unlike Funny
Multi, which is server-authoritative and can never truly go offline — Funny One has **no server
component of any kind** (D-8, 2026-09-20). The finished "story" is composed on-device from a
small layered art rig, not generated by AI, so there is no Cloudflare Worker, no R2, no per-game
cost, and no network dependency at any point in a play session.

*Amended 2026-10-05 (D-10): the game still plays from start to finish with no network, and that
stays the default. One exception is opt-in: a player who picks "From the Internet" on the start
screen gets each finished story's cartoon from Funny Multi's picture library — one download per
story, nothing uploaded. "No network, ever" and "no R2" above now describe the default, not
every session.*

## 2. Scope decisions (product owner, 2026-09-20)

## 3. Core loop (FO-CORE-\*)

- **FO-CORE-1 (MUST)** Single device; 1–7 local human "seats" plus 0–6 virtual (bot) seats; 3–7
  total participants for the classic story-rotation math to hold (mirrors FM-CORE-1's rotation
  precondition, not copied code — see `funny-one-design.md`). *Open (OQ-3): whether a genuinely
  solo 1 human + 1 virtual quick-start is wanted below that floor — confirm before T-FO-2.2.*
- **FO-CORE-2 (MUST)** **Round-robin handoff (D-8):** for each of the 7 questions, every seat
  answers in turn before the round advances; a full game is 7 rounds × (seat count) handoffs.
- **FO-CORE-3 (MUST)** "Pass to {name}" full-screen interstitial between every handoff; the
  previous answer is never visible to the next seat; an explicit "I'm {name} — go" tap resumes
  (archive ONE-7).
- **FO-CORE-4 (MUST)** Game state lives in memory in the client only (reducer/React state); no
  cross-session persistence in v1 (resume-after-close is a MAY, archive ONE-19).
- **FO-BOT-1 (MUST)** Virtual-seat picks: uniform random from the slot's pool, excluding options
  already used this round where the pool allows it — same rule Funny Multi applies server-side
  (FM-BOT-2), just invoked locally with a short comedic "thinking" delay (archive ONE-4,
  0.8–1.5 s) since there is no natural network latency to imply thought.

## 4. Reuse from `packages/shared` (FO-ARC-\*)

- **FO-ARC-1 (MUST)** Language registry, `AUTHORED_LANGUAGES` gating, `rotation.ts`
  (`storyIndex`), and the whole `pools/` tree (schema, options, per-language texts, validation
  suite) carry over **unmodified** — same content, same FM-POOL-1..6 rules, same 15 languages
  (D-2). No new authoring for text answers.
- **FO-ARC-2 (MUST)** Prose rendering (`renderProse`, `polishProse`, `polishRussianProse`)
  currently lives server-side in `apps/funny-multi-server/src/grammar.ts` / `i18n/`. Funny One
  has no server, so this must be **promoted into `packages/shared`** before either product can
  use it cleanly — a real refactor of shipped Funny Multi code, tracked as its own task
  (T-FO-2.1), not a copy-paste.
- **FO-ARC-3 (MUST NOT)** No `Room`/socket contract, no rooms/rate-limiting/disconnect-grace/host
  migration — none of it has a Funny One equivalent, because none of it exists to solve a
  problem Funny One has (there is only ever one device).

## 5. Picture mechanic — on-device rig (FO-IMG-\*)

- **FO-IMG-1 (MUST)** Scenes assembled client-side from layered rig assets: background ×
  character × co-character × prop (archive ONE-13), giving ≥ 10³ distinct visual combinations
  from a small, fixed, pre-vetted asset set (archive targeted ≥ 50k from ≤ 2 MB; exact target to
  be set once real art exists — treat 50k/2 MB as an ambition, not a locked number).
  **New content task**: none of this art exists in the repo; it must be commissioned or drawn,
  matching the existing mascot/art style already used in `apps/funny-multi-client/components/
  art/*` closely enough that both products read as one family.
  *Amended 2026-09-22 (owner): all seven story slots get rig art, not only the four scene
  slots — `when` as a badge (top-left), `why` as a thought bubble, `end` as a stamp
  (top-right), stacked above the prop in that order. Lands in three gated sub-steps
  (T-FO-4.2a/b/c). `packages/shared`'s `VISUAL_SLOTS` is deliberately unchanged — it drives
  Funny Multi's AI prompt; Funny One keeps its own rig-slot list.*
- **FO-IMG-2 (MUST)** Zero network calls during gameplay — full-precache PWA, works in airplane
  mode end-to-end, matching the archive's founding rationale for the whole product (there is no
  other way to be truly offline while Funny Multi's server-held room state cannot be).
  *Amended 2026-10-05 (D-10): holds unchanged for the built-in pictures (the default) and
  whenever the device is offline. With "From the Internet" chosen, the end screen makes one
  `GET` per finished story for its library picture, and a picture export reads that address
  once more; the service worker does not store these pictures. Rounds, hand-offs and everything
  before the end screen still make no network call. Checked by `scripts/funny-one-offline.mjs`
  (built-in path, zero calls) and T-FO-8.1's browser check (both paths).*
- **FO-IMG-3 (MUST)** Reveal uses a spring-physics layer-by-layer assembly animation (archive
  ONE-15), reusing Funny Multi's existing motion presets (`styles/motion.ts`) rather than a new
  animation system.
- **FO-IMG-4 (SHOULD)** In-round dedup: avoid assembling a visually identical scene twice in one
  session where the pool allows a different pick (archive ONE-16 equivalent).

## 6. Audience / store positioning (FO-ID-\*)

- **FO-ID-1 (MUST)** Funny One targets **Google Play Families / "Everyone" rating** eligibility
  — zero data collected, zero network calls, fixed pre-reviewed asset set (archive AND-1, CMP-2).
  This is the opposite positioning from Funny Multi (FM-ID-2: 12+, never in kids listings) and is
  only defensible *because* D-8 chose the offline rig over the AI pipeline — do not weaken this
  by introducing any network call or telemetry later without revisiting this requirement.
  *Amended 2026-10-05 (D-10): the "zero network calls" basis now holds only for the built-in
  pictures. With "From the Internet" the device downloads AI-drawn pictures made for Funny
  Multi (12+, FM-ID-2), and Cloudflare, which serves them, sees the device's IP address as any
  web host does. **Open owner decision before a Play listing:** leave the option out of the
  store app (its launch URL carries `?shell=android` so that a web deploy can do this —
  `deploy/android-funny1/README.md`), or have the library reviewed for an "Everyone" rating.
  Until that is decided, the Play Families target is unproven.*
- **FO-ID-2 (MUST)** No account, no analytics, no crash reporting that leaves the device in v1 —
  matches FO-IMG-2's zero-network claim; anything that would contradict it needs its own decision
  record, not a quiet addition.
  *Amended 2026-10-05: D-10 is that decision record for the picture download. Still no account,
  no analytics and no crash reporting.*

## 7. Open questions (confirm before the phase that needs them — see `funny-one-tasks.md`)

- **OQ-3** *(resolved 2026-09-20, owner)* Solo quick-start is allowed: 1 human + 1 virtual seat
  is a valid v1 game, no 3-total floor. Funny Multi's floor exists for room-fairness reasons that
  don't apply to a single-device app — the person holding the phone doesn't need company to
  start. T-FO-2.2's reducer must accept a 2-seat minimum (not 3).
- **OQ-4** *(resolved 2026-09-20, owner)* Yes, cross-device sharing is wanted — but via the OS
  native share sheet only (export the finished image/story to AirDrop, Bluetooth, Messages,
  email, save-to-photos, etc.), not an upload/link or any other network path. The app itself
  makes no network call to do this; the OS does any transfer, so FO-IMG-2 (offline PWA) and
  FO-ID-1 (Play Families eligibility) both stay intact as written. T-FO-4.2/4.3 should reuse
  Funny Multi's existing local `downloadStory.ts`-style export (canvas → file/share, no server)
  rather than its `/i/<hash>` upload+link pattern.
  *(2026-10-05: unchanged by D-10. Sharing is still the OS share sheet only; the picture
  download is a separate, opt-in path, and it uploads nothing.)*

  relitigate it casually: any future feature that adds a network call reopens this.)*
